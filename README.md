# G431 FOC · 有感电机控制与力反馈旋钮

基于 **STM32G431 + MT6826S SPI 编码器**的三相无刷电机控制固件，面向低速控制、直接力矩控制和力反馈旋钮实验。工程采用 C11，包含 FOC 电流环、位置/速度外环、8 种运行模式、齿槽与摩擦补偿，以及配套标定和串口遥测接口。

本 README 对应 **`codex/sensored` 分支**。当前工程固定使用 MT6826S 有感反馈，已移除无感观测器、AS5600 参考角和有感/无感构建切换；其它分支的实现与配置应分别查看。

[快速开始](#快速开始) · [控制模式](#控制模式) · [补偿与标定](#补偿与标定) · [工程结构](#工程结构) · [文档导航](#文档导航)

## 主要功能

- **有感 FOC**：U/W 两相电流采样、Clarke/Park 变换、Id/Iq PI 和 SVPWM；MT6826S 提供换相角、位置和速度反馈。
- **位置、速度与力矩控制**：支持模式允许的电位器或主机给定，执行限流、斜率和状态门控。
- **力反馈旋钮**：自由、阻尼、弹簧、档位与软限位，可调刚度、阻尼、档数和活动范围。
- **补偿**：固件内置 512 点齿槽表，支持查表插值、运行渐入、速度淡出；摩擦补偿使用库仑项与黏性项模型。
- **标定与维护**：换相方向/零角辨识、逐点/同步齿槽采集、自动摩擦采集、MT6826S 自校准和 Flash 参数保存。
- **通信与诊断**：USART2 双向协议、命令应答、状态与遥测、主机控制权和心跳失联停机；另含电机音乐与诊断强拖功能。

PC 图形上位机 **HapticKnobStudio 是独立工程**，不包含在本仓库中。本仓库的 `host/` 仅包含 PC 数据分析工具。

## 硬件与控制配置

以下是当前源码的配置，移植到其它板卡或电机前需要重新核对。

| 项目 | 当前配置 |
|---|---|
| MCU | STM32G431CBUx，Cortex-M4，主频 170 MHz |
| 存储 | 128 KiB Flash、32 KiB RAM；GNU 链接配置为程序预留 122 KiB，参数占末尾 6 KiB |
| 角度反馈 | MT6826S，SPI1，15 位机械角，32768 count/圈，CRC 与状态校验 |
| 电流采样 | ADC1 注入通道采集 U/W 相电流 |
| PWM / 电流环调度 | 约 20 kHz；这是执行频率，不是电流环闭环带宽 |
| 系统控制调度 | TIM2，1 kHz / 1 ms |
| 普通模拟输入 | ADC2 + DMA，电位器给定 |
| 上位机通信 | USART2 + DMA，921600 baud，8N1；PB3 TX / PB4 RX |
| 算法母线电压 | 固定 15.0 V，当前没有实时母线电压采样 |
| 电机配置 | `motor_config.h` 中的 GB4310 标称参数、14 极对；须与实机核对 |

MT6826S 的当前 SPI 接线为 CSN→PA4、SCK→PA5、MISO→PA6、MOSI→PA7。板级外设与引脚以 [CubeMX 配置](g431_foc.ioc)、[外设初始化](Core/Src)和[仓库原理图](SCH_Schematic1_2026-09-13.pdf)交叉核对。

核心常量位于 [`firmware/config/motor_config.h`](firmware/config/motor_config.h)。配置中的电机额定电压为 24 V，**不能据此把当前控制板的 15 V 母线配置直接改为 24 V**；供电、功率级和电机参数需要一起确认。

## 快速开始

### 1. 获取当前分支

```powershell
git clone --branch codex/sensored https://github.com/xtt02266-hue/g431_foc.git
cd g431_foc
```

### 2. 准备构建环境

| 工具 | 用途 |
|---|---|
| Arm GNU Toolchain | 提供 `arm-none-eabi-gcc`、`g++`、`objcopy` 和 `size`，均需加入 `PATH` |
| CMake ≥ 3.22 | 配置工程与构建预设 |
| Ninja | 当前预设使用的构建工具 |
| pyOCD + CMSIS-DAP 探针 | 使用仓库提供的下载/调试任务时需要 |
| STM32G4 Device Family Pack | pyOCD 识别当前目标时使用，现有任务指定 2.0.0 Pack |

固件构建不依赖 Python 回归环境或 HapticKnobStudio。Python、Unicorn、pyelftools 等仅在运行相应离线验证工具时需要。

### 3. 编译

在仓库根目录运行：

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

生成 `build/Debug/g431_foc.elf`，可直接作为下载和调试输入。

可选预设：

| 预设 | 配置与构建命令中的名称 | 产物目录 |
|---|---|---|
| 调试 | `Debug` | `build/Debug/` |
| 独立有感调试 | `sensored-debug` | `build/sensored-debug/` |
| 发布优化 | `Release` | `build/Release/` |

例如发布构建使用 `cmake --preset Release` 和 `cmake --build --preset Release`。预设和工具链配置见 [CMakePresets.json](CMakePresets.json) 与 [GNU 工具链文件](cmake/gcc-arm-none-eabi.cmake)。

**CMake 当前不会自动导出 HEX。** 如下载工具需要 Intel HEX，在 Debug 构建成功后运行：

```powershell
arm-none-eabi-objcopy -O ihex build/Debug/g431_foc.elf build/Debug/g431_foc_builtin_cogging.hex
```

内置齿槽表已经参与 ELF 链接，导出 HEX 只是转换文件格式。

### 4. 下载

VS Code 已提供以下任务：

1. `CMake: Configure Debug`
2. `CMake: Build Debug`
3. `DAPLink: Flash Debug`：先构建 Debug，再由 pyOCD 下载 ELF。

下载任务使用目标 `stm32g431cbux`、under-reset 连接与扇区擦除。Pack 路径在 [`.vscode/tasks.json`](.vscode/tasks.json) 中，默认为 `%LOCALAPPDATA%\Arm\Packs\.Download\Keil.STM32G4xx_DFP.2.0.0.pack`；使用前确认实际安装位置。

GNU 链接脚本保留了三页独立参数区：

| 数据 | 起始地址 | 大小 |
|---|---|---:|
| 摩擦参数 | `0x0801E800` | 2 KiB |
| 齿槽表与配置 | `0x0801F000` | 2 KiB |
| 电机辨识参数 | `0x0801F800` | 2 KiB |

更新程序时使用按需扇区擦除，避免整片擦除丢失已有标定。地址以 [`STM32G431XX_FLASH.ld`](STM32G431XX_FLASH.ld) 为准。现有验证使用 Arm GNU/CMake；Keil 工程与其它下载配置需要单独核对链接范围。

### 5. 连接并运行

1. 核对供电、接线、编码器和电机配置，连接兼容版本的 HapticKnobStudio，串口设为 **921600 / 8N1**。
2. 读取设备状态和参数，确认编码器数据有效。若处于 FAULT，先排除原因并清故障，再接管。
3. 如无有效电机参数，在 WAIT_PARAMETERS 状态先取得主机控制权，再执行辨识并等待保存完成。当前禁止上电自动辨识，辨识完成后仍需显式 START。
4. 参数就绪后，确认或取得主机控制权，应用所需模式与给定来源，再写入限流和模式参数，并读回确认。
5. 完成设置后 START。主机 START 会清零旧 Iq/速度目标，非零力矩或速度给定应在启动成功后重新发送；初次触觉试验可先用较小限流，步骤见[触觉调参说明](docs/触觉模式调参与逻辑检查说明.md)。
6. STOP 撤销输出并释放主机控制权；下次试验需要重新接管、应用模式，并恢复本次所需的测试限流。

固件上电默认未请求运行，默认模式为电位器力矩模式。主机持有控制权时需持续发送心跳，超时门限为 **2000 ms**。编码器有效数据超过 **2 ms** 未更新时进入故障停机；故障排除后需按状态恢复流程操作。

当前辨识流程主要确定换相方向与零角；R/L 和极对数仍取配置值，不能把辨识成功当作这些参数已全部自动测得。

## 控制模式

模式 ID、运行状态、给定来源和控制权是不同字段；选择模式不等于启动电机。

| ID | 模式 | 允许的给定来源 | 行为 |
|---:|---|---|---|
| 0 | `POSITION` | POT | 位置环生成速度目标，再经速度环生成 Iq |
| 1 | `TORQUE` | POT / HOST | 基础力矩/Iq 给定直接进入电流控制，不保持转速或位置 |
| 2 | `FREE` | INTERNAL | 轻阻力自由转动，可按配置叠加补偿 |
| 3 | `DAMPING` | INTERNAL | 产生与机械速度相反的阻尼力矩 |
| 4 | `SPRING` | INTERNAL | 围绕运行参考中心回弹，偏转越大逐渐增硬 |
| 5 | `DETENT` | INTERNAL | 离散档心吸附，带静区与换档迟滞 |
| 6 | `LIMIT` | INTERNAL | 活动范围内无虚拟墙力，越界后产生向内恢复力 |
| 7 | `SPEED` | HOST | 速度 PI 生成 Iq，支持主机速度给定和斜率 |

正常闭环模式均接入齿槽和摩擦补偿，是否输出仍取决于各自使能配置。辨识、音乐、开环强拖和标定由各自流程控制输出；停机与故障撤销输出。

### 触觉参数

| 参数 | 当前固件默认值 |
|---|---:|
| Spring 基础刚度 | 0.12 A/rad |
| Detent 基础刚度 | 0.40 A/rad |
| Limit 基础刚度 | 0.80 A/rad |
| 基础阻尼 | 0.002 A/(rad/s) |
| 档数 | 24 档/圈 |
| 软限位半范围 | ±90° |

这六项触觉参数当前仅保存在 RAM，复位后恢复固件默认值；不要把写入成功等同于已保存到 Flash。

弹簧和档心附近有静区，档位在约 55% 档距处切换；软墙只对继续越界的运动增加接触阻尼。三种位置触觉还按刚度增加阻尼，不能只用上表的基础阻尼判断最终手感。

SPRING/DETENT/LIMIT 的总电流斜率为 20 A/s，FREE/DAMPING 保留 1 A/s。位置触觉在首次实际控制周期锁定参考中心，STOP 后重启重新捕获，重复 START 不改变当前中心。连续位置使用整数计数，档位使用有界整数相位，减少长期运行后的浮点精度损失。

主机默认 Iq 限幅为 0.9 A，软件最大边界为 1.9 A；电位器力矩模式另有 ±0.2 A 总限流。这些是当前配置边界，不代表任何电机、板卡或安装条件下都可直接使用。三种触觉模式的起步参数、读回方法和曲线选择见[完整调参说明](docs/触觉模式调参与逻辑检查说明.md)。

## 补偿与标定

### 固件内置齿槽表

表存放在 [`motor_cogging_builtin.h`](firmware/compensation/motor_cogging_builtin.h)，随程序下载到 Flash，启动时载入活动表，**无需在上位机再次导入 CSV**。

| 项目 | 当前值 |
|---|---|
| 点数 / 修订号 | 512 点 / revision 10 |
| 量化单位 / CRC32 | 0.1 mA / `0x8706A889` |
| 默认启用 / 增益 | 开 / 0.90 |
| 补偿自身限幅 | ±0.080 A |
| 速度淡出 | 100 rpm 以下全量，100～200 rpm 线性淡出，200 rpm 起为零 |
| 相位偏移 / 运行渐入 | 0 count / 500 ms |

**该表是混合候选表，尚不能称为完整实测合格表。** 索引 5～511 来自 2026-10-12 的 507 个有效双向点，索引 0～4 为旧表对齐后的辅助估算。实际补偿收益、角度对齐和反向稳定性仍需验证；换电机、换编码器映射或改变机械安装后，应重新评估适用性。

恢复顺序为“固件内置默认值 → 来源标签匹配且校验通过的 Flash 保存记录”。旧来源记录不覆盖新内置表，也不会在启动时自动擦除；有效保存的禁用状态仍会恢复。故下载后若发现补偿关闭，应先读回配置，不能仅凭内置默认使能判断运行状态。

补偿电流与模式输出合成后仍受该模式总限流约束。TORQUE 的命令及目标力矩遥测表示基础给定，最终 Iq 可以包含补偿，不能把目标力矩当成轴端实测力矩。

### 摩擦与重新标定

摩擦模型为 `Ic × tanh(rpm / smooth_rpm) + Kv × rpm`，出厂默认禁用，可通过配置或有效 Flash 记录启用。FREE 保留轻微附加阻尼，其它触觉模式使用纯摩擦模型。标定会话单独控制补偿，正式逐点采样不叠加齿槽或摩擦辅助。

- [逐点齿槽标定](docs/逐点齿槽标定使用与协议.md)：定位、稳定判定、逐点采集及质量条件。
- [同步齿槽标定](docs/同步齿槽标定使用与协议.md)：连续采样、正反转与对照流程。
- [摩擦补偿完整流程](docs/摩擦补偿完整操作流程.md) / [自动摩擦采集](docs/自动摩擦采集使用与协议.md)。
- [MT6826S 自校准](docs/MT6826S编码器自校准.md)：校准前停用旧表，完成后按要求完整断电重启，并重新核对补偿对齐。

## 工程结构

```text
Core/                       CubeMX 入口、外设初始化与中断
Drivers/                    STM32 HAL / CMSIS
firmware/
  app/                      状态机、模式、主机控制与标定会话
    private/                应用内部状态和辅助接口
  control/                  电流环、速度环、位置环、轨迹与 SVPWM
  compensation/             齿槽、摩擦模型及存储
  calibration/              参数辨识、采集和编码器自校准
  communication/            协议解析、序列化与 UART DMA
  drivers/                  MT6826S、编码器与模拟输入等驱动
  platform/                 板级初始化与电流偏置校准
  algorithm/                PID 等计算模块
  config/                   电机参数与控制常量
  music/                    电机音乐调制和曲目
  diagnostics/              诊断与调试输出
host/                       PC 历史数据分析工具
docs/                       架构、操作与协议说明
refactor_validation/        正式离线测试与验证记录
```

执行分工如下；Flash 擦写和协议发送不放在电流控制中断中。

| 执行上下文 | 主要职责 |
|---|---|
| ADC 注入转换中断，约 20 kHz | 电流采样、角度快照使用、FOC 与 PWM 更新 |
| TIM2 中断，1 kHz | 辨识推进、运行状态、反馈更新、外环与触觉输出 |
| `main()` 前台 | 参数事务与保存、协议处理和发送、编码器自校准寄存器事务 |

模块边界、补偿方向和触觉模型公式见[架构说明](docs/architecture.md)。

| 项目 | 已记录结果 |

| 下载数据检查 | ELF/HEX 数据一致，内置表 CRC 一致，下载范围未覆盖参数页 |
| 实机验收 | 上述离线记录不覆盖实际烧录、ISR 最坏耗时、负载稳定性、温升及最终手感 |

正式验证工具在 `refactor_validation/`；部分用例需要本地候选 CSV 和历史基线 ELF。这些文件与详细 JSON 报告、编译产物未纳入仓库，**新克隆不能直接复现全部历史回归**，前提和运行方式见对应记录。

当前没有实时母线电压补偿、逆变器死区/器件压降补偿或扰动观测器闭环。供电压降、低速测量误差和小电流跟踪仍需结合实机数据分析，不能通过已有离线通过项推断已解决。
