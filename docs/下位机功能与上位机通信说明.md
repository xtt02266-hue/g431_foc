## 1. 系统概览

当前下位机运行在 STM32G431 上，主要完成：

- 三相无刷电机 FOC 电流闭环；
- MT6826S 15位SPI有感换相和机械速度估算；
- 电机参数加载、辨识与 Flash 保存；
- 位置、直接力矩和四种触觉模式；
- 电机音乐播放；
- 并行无感观测器；
- OLED 状态显示；
- USART2 与 HapticKnobStudio 双向通信；
- 上位机接管、命令确认、状态回报、遥测和失联停机。

控制系统分为三个时间层：

| 层级 | 执行位置 | 典型频率 | 主要工作 |
|---|---|---:|---|
| 快速电流层 | ADC 注入转换完成中断 | 约 20 kHz | SPI角度快照、电流采样、Clarke/Park、Id/Iq PI、反Park、SVPWM |
| 系统控制层 | TIM2 周期中断 | 1 kHz | 状态机、速度估算、位置/力矩/触觉模式、心跳超时 |
| 后台服务层 | `main()` 主循环 | 尽快循环 | 参数保存、串口协议解析、ACK/STATUS/遥测、OLED |

## 2. 当前硬件与基础配置

### 2.1 主要外设

| 外设 | 当前用途 |
|---|---|
| TIM1 | 三相互补 PWM，并触发 ADC 注入采样 |
| ADC1 | U/W 两相电流注入采样 |
| ADC2 | 用户电位器等普通 ADC DMA 采样 |
| TIM2 | 1 ms 系统控制任务 |
| SPI1 | MT6826S 15位绝对角度，作为实际换相、位置和速度反馈源 |
| I2C1 | 保留外设配置，当前控制链路不再读取AS5600 |
| USART2 + DMA | 上下位机双向通信，921600、8N1 |
| OLED | 故障、参数及辨识状态提示 |

### 2.2 MT6826S接线与SPI格式

| MT6826S信号 | STM32G431引脚 | 说明 |
|---|---|---|
| CSN | PA4 | 软件片选，低电平有效 |
| SCK | PA5 | SPI1 SCK |
| MISO | PA6 | SPI1 MISO，内部上拉用于识别断线 |
| MOSI | PA7 | SPI1 MOSI |
| VDD/GND | 3.3 V/GND | 与控制板共地，禁止接5 V逻辑 |

SPI1使用Mode 3（CPOL=1、CPHA=1）、MSB first、约10.625 MHz。每次读取保持CSN为低并发送16位连读命令`0xA003`，随后读取寄存器`0x003～0x006`：15位角度、3位状态和CRC8。CRC使用多项式`0x07`、初值`0x00`；CRC错误、SPI传输错误、磁场过弱或欠压都会使该次角度失效。控制链只读取最后一个通过校验的快照，超过2 ms没有新有效数据时停机并进入FAULT。

### 2.3 电机与安全相关配置

配置集中在 `user/inc/motor_config.h`：

| 配置 | 当前值 | 含义 |
|---|---:|---|
| `SYSTEM_BUS_VOLTAGE` | 15.0 V | 算法使用的固定母线电压；硬件当前没有实时母线采样 |
| `MOTOR_TORQUE_CURRENT_LIMIT_A` | 1.5 A | 普通力矩给定的软件硬上限 |
| `MOTOR_HOST_DEFAULT_IQ_LIMIT_A` | 0.10 A | 上位机每次接管后的默认会话限流 |
| `MOTOR_HOST_HEARTBEAT_TIMEOUT_MS` | 500 ms | 上位机心跳丢失后的停机时间 |
| `MOTOR_IQ_SLEW_A_PER_S` | 1.0 A/s | HOST Iq 和触觉 Iq 的变化率限制 |
| `MOTOR_PARAMETERS_AUTO_IDENTIFY` | 0 | 参数缺失时不自动开始辨识 |
| `MOTOR_TORQUE_POT_MAX_CURRENT_A` | 0.2 A | 本地电位器力矩模式的最大电流 |
| `MOTOR_TORQUE_CONSTANT_NM_PER_A` | 8.27/291 | 根据 291 KV 估算的 Kt，不是实测值 |

下位机当前默认工作模式是 TORQUE，默认输入来源是 POT，但上电后 `run_requested=0`，因此不会自动开始出力。

## 3. 上电初始化流程

程序从 `Core/Src/main.c` 进入，CubeMX 先初始化 GPIO、DMA、ADC、TIM、I2C、USART 和 SPI，随后调用 `hardware_init()`。

```mermaid
flowchart TD
    A[main] --> B[HAL_Init 与系统时钟]
    B --> C[CubeMX 外设初始化]
    C --> D[hardware_init]
    D --> E[等待外设稳定 100 ms]
    E --> F[ADC1/ADC2 自校准]
    F --> G[启动用户 ADC DMA]
    G --> H[初始化MT6826S并取得首个SPI角度]
    H --> I[启动 TIM1 CH4 ADC触发]
    I --> J[500次电流零偏采样]
    J --> K[启动ADC注入中断]
    K --> L[启动三相互补PWM通道]
    L --> M[SVPWM_Init 零矢量安全状态]
    M --> N[VOFA_Init: 协议初始化与UART RX DMA]
    N --> Q[OLED初始化]
    Q --> R[Motor_System_Init]
    R --> S[从Flash加载电机参数]
    S --> T[启动TIM2 1kHz中断]
    T --> U[进入主循环]
```

需要注意：代码会启动 TIM1 的物理 PWM 通道，但 `SVPWM_Init()` 将输出置于安全零矢量状态；真正闭环输出还要经过系统状态机调用 `SVPWM_Enable()` 和 `Motor_CurrentLoop_Enable(1)`。

参数加载结果决定初始状态：

- Flash 参数有效：下一次状态更新进入 STOPPED，等待显式 START；
- Flash 无有效参数：进入 WAIT_PARAMETERS；因为自动辨识关闭，不会自行驱动电机辨识；
- 参数记录错误或后续辨识失败：进入 FAULT。

## 4. 主循环和中断关系

### 4.1 后台主循环

`main()` 中持续执行：

```text
Motor_Parameters_BackgroundTask()
PC_Protocol_Task()
Motor_ShowDebugInfo_OLED()
```

各函数职责：

- `Motor_Parameters_BackgroundTask()`：参数辨识结束后的 Flash 保存等慢操作；
- `PC_Protocol_Task()`：从串口环形缓冲取数据、拆帧、CRC 校验、执行命令和发送周期 STATUS；
- `Motor_ShowDebugInfo_OLED()`：刷新 OLED，并每 5 ms 尝试发送一次 Studio v2 遥测。

串口解析、CRC、数据封包、OLED 和 Flash 操作均不放入 20 kHz 电流环。

### 4.2 1 kHz 系统任务

TIM2 每 1 ms 调用 `HAL_TIM_PeriodElapsedCallback()`：

```mermaid
flowchart TD
    A[TIM2 1ms中断] --> B[Motor_Parameters_ControlTask1ms]
    B --> C[Motor_System_UpdateOperatingState]
    C --> D[Motor_System_Task]
    D --> E[状态LED计数]

    C --> F{参数/传感器/故障/运行请求}
    F -->|不满足| G[统一安全停机]
    F -->|满足| H[使能电流环和SVPWM]

    D --> I[速度估算和连续角展开]
    I --> J[检查HOST心跳超时]
    J --> K[读取并滤波电位器]
    K --> L{MotorState与ControlMode}
    L --> M[位置模式]
    L --> N[力矩模式]
    L --> O[Free/触觉模式]
    L --> P[音乐独占]
```

### 4.3 约 20 kHz 电流环

TIM1 触发 ADC1 注入采样，转换完成后进入 `HAL_ADCEx_InjectedConvCpltCallback()`：

1. 读取 U/W 两相原始电流；
2. 对采样做一阶滤波；
3. 调用 `Motor_CurrentLoop_Run()`；
4. 在电流环内部完成电流重构、Clarke/Park 变换；
5. Id/Iq PI 计算目标电压；
6. 反 Park 得到 α/β 电压；
7. SVPWM 更新三相占空比。

1 kHz 系统层只生成 `target_d/target_q`，不会把串口和触觉界面逻辑塞入快速电流中断。

### 4.4 MT6826S机械速度估算

ADC/FOC中断通过SPI刷新MT6826S 15位角度缓存，其他模块只读取这一快照，避免多个上下文争用SPI。速度估算处理0/32767回绕并展开成连续机械位置，使用20/10/5 ms自适应滚动窗；结果每1 ms更新并经过`alpha=0.4`的一阶低通。

系统使用20/10/5 ms自适应滚动位置窗：15位编码器在低速20 ms窗口的分辨率约为`0.0916 rpm/count`，中高速缩短窗口以降低反馈延迟。窗口切换带迟滞，而且所有窗口都每1 ms发布速度。当前速度PI基线为`Kp=0.0016`、`Ki=0.0001`、`Kd=0`，仍需更换编码器后的真机复测。

## 5. 电机系统状态机

`MotorState` 表示电机当前实际运行状态，与“选择了什么工作模式”是两件事。

| 值 | 状态 | 进入条件和行为 |
|---:|---|---|
| 0 | STOPPED | 参数有效、编码器有效，但没有运行请求；关闭电流环和SVPWM |
| 1 | WAIT_PARAMETERS | Flash 中没有可用电机参数；保持安全停机 |
| 2 | IDENTIFYING | 电机参数辨识占用 PWM，普通模式暂停 |
| 3 | SENSORED_RUN | 参数、MT6826S SPI角度和运行请求均有效；执行所选模式 |
| 4 | MUSIC | 音乐模块独占 q 轴给定，普通控制模式暂停 |
| 5 | FAULT | 参数错误或MT6826S SPI数据超过2 ms未更新；故障锁存并停机 |

统一安全停机 `Motor_System_ForceSafeStop()` 会：

- 将保存的力矩给定和 Id/Iq 目标清零；
- 清速度环积分、位置环状态和轨迹状态；
- 停止音乐；
- 关闭无感观测器；
- 关闭电流环；
- 禁用 SVPWM。

`CLEAR_FAULT`只在参数已准备好且MT6826S数据恢复新鲜时成功。清故障不会自动START。

## 6. 当前八种工作模式

工作模式由 `MotorControlMode` 表示，输入来源由 `MotorInputSource` 独立表示。

| 模式 | 值 | 合法来源 | 当前行为 |
|---|---:|---|---|
| POSITION | 0 | POT | 电位器目标→位置环→速度环→Iq |
| TORQUE | 1 | POT/HOST | 电位器映射力矩，或接受上位机直接 Iq 给定 |
| FREE | 2 | INTERNAL | 根据实际转速输出动态摩擦补偿，并可叠加齿槽LUT |
| DAMPING | 3 | INTERNAL | 根据机械角速度产生反向阻尼电流 |
| SPRING | 4 | INTERNAL | 根据连续位置偏离中心的距离产生恢复力并叠加阻尼 |
| DETENT | 5 | INTERNAL | 将连续角度吸向最近的等间隔档位并叠加阻尼 |
| LIMIT | 6 | INTERNAL | 超出中心两侧软范围后产生返回力 |
| SPEED | 7 | HOST | 接受目标RPM，用速度PI维持恒速并可叠加摩擦和齿槽补偿 |

### 6.1 POSITION

```text
ADC电位器
  → 4095-raw反向映射
  → EMA低通
  → 目标位置
  → 位置环生成机械目标速度
  → uvw_dir统一电磁方向
  → 速度PI
  → target_q
```

POSITION 目前只能使用 POT，尚未开放上位机直接位置目标。当前采用无外加负载时期的纯位置/速度级联参数，位置模式不叠加摩擦或惯性前馈。

### 6.2 TORQUE

POT 来源：电位器中点带死区，映射为目标力矩，再使用估算 Kt 转换为 Iq。当前最大值是 ±0.2 A。

HOST 来源：上位机通过 `SET_IQ` 给定 Iq。给定值先受当前会话 `iq_limit` 限制，再按 1.0 A/s 斜率送入电流环。START 后初始 Iq 必定为 0，上位机需要重新发送目标。

### 6.3 触觉模式

下位机将MT6826S单圈计数展开成连续机械角度。相邻样本跨越0/32767时使用最短角差，因此正常跨圈不会让角度突然跳回。

设：

- `θ`：连续机械角度；
- `center`：本次 START 捕获的中心角；
- `ω`：机械角速度；
- `uvw_dir`：辨识得到的机械方向到电磁 Iq 方向的映射；
- `i_mech`：机械方向下计算的目标电流。

当前公式：

```text
FREE:     i_mech = Ic·tanh(rpm/smooth_rpm) + Kv·rpm
DAMPING:  i_mech = -B·ω
SPRING:   i_mech = -K·(θ-center) - B·ω
DETENT:   nearest = center + round((θ-center)/spacing)·spacing
          i_mech = -K·(θ-nearest) - B·ω
LIMIT:    仅超出 ±half_range 时计算恢复力

最终 Iq = uvw_dir · i_mech + cogging_iq(angle)
```

最终 Iq 经过有限值检查、会话限流和 1.0 A/s 斜率限制。Spring、Detent 和 Limit 每次 START 时重新捕获中心。触觉 START 前要求辨识结果中的 `uvw_dir` 必须为 +1 或 -1。

FREE 的摩擦补偿参数包含 `enabled`、库仑电流 `Ic`、粘性系数 `Kv`、过零平滑速度和最大补偿电流。唯一生效模型是`Iq=Ic·tanh(rpm/smooth)+Kv·rpm`；旧的惯性前馈和重复摩擦公式已经移除。默认参数为 `Ic=0.02 A`、`Kv=0`、`smooth=20 rpm`、`max=0.03 A`，上电后默认关闭，必须由上位机停机写入并启用。参数由摩擦模块统一做有限值和范围校验。零速时 `tanh(0)=0`，不会自行选择转动方向。

齿槽补偿使用512点MT6826S单圈位置域查找表。每点是0.1 mA分辨率的`int16` q轴补偿电流，共1024字节。每格对应64个编码器计数，并在相邻点间循环线性插值。配置包含启用、整体增益、独立电流限幅、0～32767 count相位偏移，以及高速淡出的起止转速。

默认`gain=0.3`、独立限幅`0.03 A`；30 rpm以下全量应用，30～100 rpm线性淡出，100 rpm以上输出为零。每次START后有效增益在500 ms内从0上升，STOP和故障立即归零。补偿只作用于SPEED和FREE，不改变POSITION、TORQUE、DAMPING、SPRING、DETENT或LIMIT。

RAM中保留`active[512]`和`staging[512]`两张表。串口只写staging；512点接收完整且CRC32匹配后，COMMIT才原子交换指针。任何缺包、超时或CRC错误都保留旧active表。

默认触觉参数：

| 参数 | 默认值 |
|---|---:|
| Spring K | 0.03 A/rad |
| Damping B | 0.002 A/(rad/s) |
| Detent K | 0.05 A/rad |
| Limit K | 0.05 A/rad |
| Limit 半范围 | 90° |
| Detent 档位数 | 24 |

### 6.4 SPEED

SPEED 使用 `HOST` 来源。上位机运行中通过 `SET_SPEED` 设置 `-400～+400 rpm`，下位机以 `1000 rpm/s` 斜率改变内部目标，再由速度PI产生Iq。SPEED的摩擦前馈使用斜坡后的目标速度，因此实际速度尚为零时就能给出起步电流，减少静摩擦造成的积分累积和突然挣脱；FREE仍使用实际速度，保证静止时不自驱。停止或换向速度命令会清除旧方向积分。速度PI的输出上下限会扣除当前摩擦与齿槽前馈占用的电流余量，防止最终Iq已达到会话限流时积分继续增长。SPEED最终Iq使用`5 A/s`变化率以便及时从驱动切换到制动，FREE触觉继续使用`1 A/s`保持手感平滑。

## 7. 其他已有功能

### 7.1 电机参数

参数模块支持：

- 从预留 Flash 区读取电阻、电感、零位、极对数和 `uvw_dir`；
- CRC32 和字段范围校验；
- 主动调用 `Motor_System_IdentifyAndSave()` 开始辨识；
- 辨识完成后在后台写入 Flash；
- 使用辨识的 R/L 自动整定电流环带宽。

当前 `MOTOR_PARAMETERS_AUTO_IDENTIFY=0`，所以没有参数时只进入 WAIT_PARAMETERS。上位机先在WAIT_PARAMETERS状态点击“接管控制”，再点击“重新辨识并保存”，会发送带会话令牌的`IDENTIFY_AND_SAVE(0x13)`。只有编码器数据有效且辨识模块空闲时才会开始；辨识期间电机会转动，完成后参数在后台写入Flash并回到STOPPED。

### 7.2 音乐

支持有限次数和循环播放，默认不自动播放。音乐播放时使用 20 kHz 音频采样参数生成 q 轴电流，普通位置、力矩和触觉模式暂停。当前上位机协议没有音乐控制命令。

### 7.3 无感观测

无感观测器可以配置和启停，目前仅作为并行观察功能，不替代MT6826S换相。系统安全判断以SPI角度数据新鲜度为准。

### 7.4 OLED

OLED 当前主要显示 Fault、NoParam、ParamErr、辨识状态等。正常运行时详细 OLED 刷新默认关闭，以减少前台开销。

## 8. 上下位机通信架构

### 8.1 串口参数

```text
USART2
921600 baud
8 data bits
no parity
1 stop bit
no hardware flow control
RX DMA + idle event
TX DMA
```

当前正式通信使用 Studio Protocol v2。`vofa_usart.c` 中旧 JustFloat 发送函数仍存在，供历史代码调用，但当前 `motor_debug.c` 不再发送裸 JustFloat，避免它与 ACK/STATUS 混在同一字节流中。

### 8.2 v2 帧格式

```text
A5 5A | Version | Type | Seq | Length | Payload | CRC16
 2B       1B       1B    2B      2B       N       2B
```

- Version 固定为 2；
- Seq、Length、整数和 float32 均为 little-endian；
- Payload 最大 256 字节；
- CRC16-CCITT-FALSE 覆盖 Version 到 Payload；
- poly=0x1021、init=0xFFFF，结果小端发送；
- `123456789` 的标准 CRC 结果为 `0x29B1`。

Type：

| 值 | 类型 | 方向 |
|---:|---|---|
| 1 | COMMAND | PC→STM32 |
| 2 | RESPONSE | STM32→PC |
| 3 | STATUS | STM32→PC，周期主动上报 |
| 4 | TELEMETRY | STM32→PC，周期遥测 |

### 8.3 下行接收流程

```mermaid
sequenceDiagram
    participant PC as HapticKnobStudio
    participant UART as USART2 RX DMA
    participant Ring as 2048B环形缓冲
    participant Proto as PC_Protocol_Task
    participant Motor as Motor_System

    PC->>UART: v2 COMMAND帧
    UART->>Ring: Idle回调仅复制字节并重启DMA
    Ring->>Proto: 主循环每次最多处理512字节
    Proto->>Proto: 帧头/版本/长度/CRC检查
    Proto->>Motor: 调用统一Host控制接口
    Motor-->>Proto: MotorCommandResult与实际值
    Proto-->>PC: RESPONSE，回传相同Seq
    Motor-->>PC: 周期STATUS与TELEMETRY
```

UART 回调不计算触觉、不操作 Flash、不更新 PWM。坏 CRC 或版本错误的帧不会执行。接收环形缓冲溢出会计数并在 STATUS 中上报。

### 8.4 命令 Payload 与应答

COMMAND Payload：

```text
command_id:u8 | session_token:u32 | command_body
```

RESPONSE Payload：

```text
command_id:u8 | result:u8 | session_token:u32 |
config_revision:u32 | response_body
```

上位机使用 Seq 将命令和应答关联。固件缓存最近一条普通有副作用命令及其应答；完全相同的重发只重放应答，不重复执行副作用。HELLO、STOP和HEARTBEAT不进入缓存，相同 Seq 对应不同的已缓存命令时返回 `SEQ_CONFLICT`。

### 8.5 命令表

| ID | 命令 | 是否需要HOST token | 当前作用 |
|---:|---|---|---|
| 0x01 | HELLO | 否 | 返回固件版本、UID、模式能力、硬限流、默认限流、最大Payload和心跳超时 |
| 0x02 | GET_STATUS | 否 | 立即读取状态结构 |
| 0x03 | CLAIM_CONTROL | 否 | STOPPED下取得HOST控制权并返回新token |
| 0x04 | RELEASE_CONTROL | 是 | 停机、清零并回到LOCAL/TORQUE/POT |
| 0x05 | HEARTBEAT | 是 | 刷新会话存活时间并返回STATUS |
| 0x10 | START | 是 | 检查参数、故障和编码器后请求运行 |
| 0x11 | STOP | 否 | 无条件请求安全停机并释放HOST控制权 |
| 0x12 | CLEAR_FAULT | 否 | 条件满足时清除锁存故障，不启动 |
| 0x20 | SET_MODE | 是 | STOPPED下设置模式和输入来源 |
| 0x21 | SET_IQ | 是 | 仅 TORQUE+HOST+SENSORED_RUN 接受 |
| 0x22 | SET_IQ_LIMIT | 是 | STOPPED下设置本次HOST会话限流 |
| 0x23 | SET_HAPTIC_PARAMS | 是 | STOPPED下原子更新完整触觉参数集 |
| 0x24 | GET_PARAMS | 是 | 返回当前模式、来源、限流、斜率和触觉参数 |
| 0x25 | SET_FRICTION_PARAMS | 是 | STOPPED下写入启用标志和4个摩擦参数，Body为`u8+4×f32` |
| 0x26 | GET_FRICTION_PARAMS | 是 | 读取当前摩擦参数，返回`u8+4×f32` |
| 0x27 | SET_SPEED | 是 | 仅SPEED+HOST+SENSORED_RUN接受f32目标RPM |
| 0x28 | SET_COGGING_CONFIG | 是 | STOPPED下写入`enabled:u8, gain:f32, max_iq:f32, fade_start:f32, fade_end:f32, phase:u16` |
| 0x29 | GET_COGGING_CONFIG | 是 | 读取配置、LUT版本、CRC和Flash保存状态 |
| 0x2A | COGGING_TABLE_BEGIN | 是 | STOPPED下声明512点长度和整表CRC32，返回事务号 |
| 0x2B | COGGING_TABLE_CHUNK | 是 | 按事务号、偏移和数量写入最多120个`i16`表项；支持乱序与重复分包 |
| 0x2C | COGGING_TABLE_COMMIT | 是 | 检查全部分包及CRC后原子切换active表 |
| 0x2D | GET_COGGING_TABLE_CHUNK | 是 | 分段读取当前active表，每次最多120点 |
| 0x2E | SAVE_COGGING_TO_FLASH | 是 | 仅STOPPED+HOST时把当前配置和active表写入专用Flash页 |

齿槽上传事务的空闲超时为2秒。BEGIN或传输失败不会修改active表。Flash记录位于`0x0801F000`的独立2 KB页；原电机辨识参数仍位于`0x0801F800`，地址保持不变。记录含magic、格式版本、配置、512点表、表CRC和整记录CRC；上电校验失败时关闭补偿并使用零表。

### 8.6 命令结果码

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | OK | 命令接受 |
| 1 | INVALID_LENGTH | Payload 长度不正确 |
| 2 | INVALID_VALUE | 数值非法、越界、NaN或Inf |
| 3 | UNSUPPORTED | 命令不支持 |
| 4 | NOT_OWNER | token不正确或当前不是HOST控制 |
| 5 | MUST_STOP_FIRST | 必须先STOP才能执行 |
| 6 | NOT_READY | 参数或编码器尚未准备好 |
| 7 | FAULT_ACTIVE | 当前存在锁存故障 |
| 8 | BUSY | 辨识、音乐或其他控制权正在占用 |
| 9 | NOT_RUNNING | 当前不是正常运行状态 |
| 10 | INVALID_COMBINATION | 模式和来源组合非法 |
| 11 | SEQ_CONFLICT | 同一Seq对应了不同命令内容 |

上位机普通命令一次只保留一个待确认请求，200 ms 未收到 ACK 会用同一 Seq 和内容重试，最多两次。STOP 会清除上位机待发命令，并使用两个不同 Seq 连续发送两次。下位机不对 HELLO 和 STOP 使用旧请求重放缓存，因此上位机重连后 Seq 从 1 重新开始也不会阻止安全停机。

## 9. 控制权、模式和START的关系

三个概念不能混用：

| 概念 | 示例 | 表示什么 |
|---|---|---|
| Owner | LOCAL/HOST | 谁能修改运行配置 |
| Mode | TORQUE/SPRING等 | 1 kHz任务采用哪种控制算法 |
| MotorState | STOPPED/SENSORED_RUN等 | 电机现在是否真正运行 |

上位机正常控制顺序：

```mermaid
sequenceDiagram
    participant UI as 上位机UI
    participant MCU as 下位机

    UI->>MCU: HELLO
    MCU-->>UI: 能力、限流、协议参数
    MCU-->>UI: STATUS: STOPPED/LOCAL
    UI->>MCU: CLAIM_CONTROL
    MCU-->>UI: OK + session_token
    loop 每100ms
        UI->>MCU: HEARTBEAT(token)
        MCU-->>UI: STATUS
    end
    UI->>MCU: SET_IQ_LIMIT(0.10A)
    MCU-->>UI: OK + 实际值
    UI->>MCU: SET_MODE(TORQUE, HOST)
    MCU-->>UI: OK + config_revision
    UI->>MCU: START
    MCU-->>UI: OK
    MCU-->>UI: STATUS: SENSORED_RUN
    UI->>MCU: SET_IQ(0.03A)
    MCU-->>UI: OK + 接受值
    UI->>MCU: STOP
    MCU-->>UI: OK
    MCU-->>UI: STATUS: STOPPED/LOCAL
```

规则：

- 连接串口不会自动取得控制权，也不会自动启动；
- 只有 STOPPED 状态可以 CLAIM；
- 运行中不能切模式、改限流或改触觉参数；
- 模式按钮只改变上位机草稿，点击“应用所选模式”才发送 SET_MODE；
- SET_MODE 不包含 START；
- START 后 TORQUE+HOST 从 0 A 开始，不恢复旧 Iq；
- STOP 不要求 token，任何会话都可请求停机；
- STOP、释放控制权和心跳超时都会清零并回到 LOCAL/TORQUE/POT；
- 清故障和重新连接都不会自动恢复运行。

### 9.1 心跳失联保护

上位机取得 token 后每 100 ms 发送 HEARTBEAT。下位机 1 kHz任务检查：

```text
当前Owner == HOST
且 当前时间 - 最近有效心跳 > 500 ms
    → Motor_System_ReleaseHost()
    → 安全停机
    → 清零旧给定
    → Owner切回LOCAL
    → Mode/Source恢复TORQUE/POT
```

该功能用于应对拔线、关闭程序和PC进程崩溃。串口 STOP 及心跳超时属于软件保护，不是独立硬件急停。

## 11. 上位机收到数据后的处理

配套上位机主要模块：

| 文件 | 作用 |
|---|---|
| `haptic_knob_studio/protocol.py` | v2编解码、CRC、命令枚举、STATUS和遥测解析 |
| `serial_worker.py` | 后台串口读写、分包、向Qt线程发送Packet和Telemetry信号 |
| `main_window.py` | 控制权、ACK超时重试、100 ms心跳、状态显示和操作流程 |
| `cogging.py` | 正反转筛选、稳态分箱、去异常、互相关对齐、合成和平滑 |
| `channels.py` | 19路schema 4名称和单位 |
| `realtime_plot.py` | 12000点缓存、20 Hz绘图、暂停和CSV导出 |

关系如下：

```text
STM32 TELEMETRY
  → SerialWorker读取字节
  → ProtocolParser验证v2帧和CRC
  → decode_telemetry得到19路float
  → MainWindow更新状态卡片
  → RealtimePlot缓存与绘图

STM32 STATUS
  → decode_status
  → 更新实际State/Mode/Source/Owner
  → 按实际状态启用或禁用控制按钮

STM32 RESPONSE
  → 使用Seq匹配待确认命令
  → OK时提交界面状态
  → 拒绝时显示MotorCommandResult
  → NOT_OWNER时清除本地token
```

上位机显示的“实际模式”来自 STATUS，不根据用户最后点击的按钮猜测；“已发送”也不表示下位机已经执行，只有 RESPONSE=OK 才算确认。

## 12. 典型联调流程

### 12.1 只看数据

1. 烧录当前固件并上电；
2. 运行 `D:/WorkDocument/HapticKnobStudio/run_app.bat`；
3. 选择 USART2 对应的 COM 口和 921600；
4. 连接后等待 HELLO、STATUS 和遥测；
5. 不接管即可观察数据，电机保持 STOPPED。

### 12.2 更换为MT6826S后的首次辨识

旧AS5600的电角度零偏不能用于MT6826S。固件把电机参数和齿槽表的Flash版本均提升到2，首次烧录后旧记录会被判为无效，这是预期行为。

1. 接好MT6826S，先保持电机轴可以安全转动且不带外部负载；
2. 烧录`build/Debug/g431_foc.elf`并上电；
3. 打开上位机并连接串口，确认编码器状态显示“MT6826S正常”；若显示角度无效，先检查PA4～PA7、供电、磁铁距离和SPI Mode 3；
4. 此时Motor State应为WAIT_PARAMETERS。点击“接管控制”，确认Owner变为HOST；
5. 点击“重新辨识并保存”。下位机将依次测量电阻、电感、相序/极对数和电角度零位，期间电机会转动；
6. 等待Motor State从IDENTIFYING回到STOPPED，再断电重启一次，确认仍能进入STOPPED；
7. 先按0.10 A会话限流做低电流方向测试；
8. 原齿槽LUT已失效，完成基本闭环验证后按12.5节重新标定。摩擦参数当前只保存在RAM，重启后也需重新写入。

### 12.3 首次直接力矩测试

1. 固定电机并确保 Flash 中已有有效参数；
2. 连接后确认 STOPPED、角度有效；
3. 点击“接管控制”，确认 Owner=HOST；
4. 设置 `Iq_limit=0.10 A`；
5. 选择 Torque 并应用；上位机会发送 TORQUE+HOST；
6. 点击 START，等待 SENSORED_RUN；
7. 按 `+0.03 → 0 → -0.03 → 0 A` 测试；
8. 对照 `iq_applied_target`、`iq_pi_target`、`iq_actual`；
9. 点击 STOP，确认状态回到 STOPPED/LOCAL。

### 12.4 摩擦补偿标定

1. STOP并接管控制，先读取当前摩擦参数；首次粗测关闭摩擦和齿槽补偿。若低速粘滑导致无法形成稳态，可先用中高速结果写入初步摩擦参数，再启用它采低速残差；齿槽补偿始终保持关闭。
2. 切到SPEED+HOST并START，在上位机开始摩擦采样。
3. 依次发送至少三组正负配对速度，例如`±5、±10、±20 rpm`；每个方向稳定采满至少2个机械圈。
4. 上位机对每档丢弃前1.5秒，只保留目标已到位、方向正确且实际速度误差不超过`max(3 rpm, 目标25%)`的数据。
5. 每档使用`speed_loop_iq + friction_iq`还原维持匀速所需的总电流，组合正反转电流幅值，以非负约束拟合`Ic`、`Kv`并搜索`smooth`；预览会报告RMSE、R²和正反方向不对称度。
6. STOP并重新接管，将拟合结果写入下位机。再次运行相同速度档，检查速度环Iq是否下降且最终Iq没有持续限幅。

摩擦配置目前保存在RAM中，MCU复位后恢复默认关闭。标定时要求无外加负载，电机温度应尽量一致；明显的正反方向不对称通常说明负载、线缆拖拽或机械装配存在方向性影响。

### 12.5 齿槽补偿标定

1. 在STOPPED状态关闭齿槽补偿并写配置；摩擦参数可以启用。
2. 切到SPEED+HOST，设`+20 rpm`并START，点击“开始正转采样”；建议采6圈，分析时丢弃首个过渡圈。
3. 停止采样，设`-20 rpm`，同样采集反转数据。原始CSV记录时间、MT6826S 15位计数、方向、目标/实际速度、速度环Iq、实际Iq和固件版本。
4. 点击“分析采样并生成512点LUT”。每个方向只保留符号正确且速度误差不超过`max(3 rpm, 目标值25%)`的点；按MT6826S角度分512格并做去异常均值。
5. 算法通过循环互相关对齐正反曲线，用`(Iq正+Iq反)/2`抵消方向相关摩擦，再去直流并轻度循环平滑。任一方向覆盖率低于95%或平均每格少于5点时禁止生成并报告缺失格。
6. 在预览中检查正转、反转、合成LUT、峰值、RMS、相关性和相位修正量。
7. STOP并重新接管后上传到RAM。上位机依次发送BEGIN、最多120点的CHUNK和COMMIT；仅完整且CRC正确时切换active表。
8. 写配置：初次使用`gain=0.3`、`max_iq=0.03 A`、30 rpm开始淡出、100 rpm关闭。START后在SPEED和FREE进行补偿前后对比，同时观察CH14、CH15、最终Iq和限流情况。
9. 对比完成后勾选确认项，STOP并重新接管，再显式点击保存到Flash。未点击保存时重启会恢复上一次Flash记录。

残差迭代时保持补偿启用，重新采样后勾选残差更新。上位机按`新表=旧表+0.3×残差表`生成，减少一次学习过度的风险。

### 12.6 能接收数据但 STOP 无响应

按以下顺序检查：

1. 上位机连接后必须能收到 `HELLO RESPONSE` 和 `STATUS`；仅有字节速率、没有实际状态字段，不能证明新版双向协议已连通。
2. 确认已烧录当前 `build/Debug/g431_foc.elf`。旧 JustFloat 固件只会上报浮点数据，不认识 v2 命令。
3. USART2 使用 `921600, 8N1`，MCU 引脚为 `PB3=TX`、`PB4=RX`。
4. USB 转串口的 `TX` 必须连接 MCU `PB4`，其 `RX` 连接 MCU `PB3`，并连接公共 `GND`；电平必须是 3.3 V TTL。
5. 点击 STOP 后应先看到“STOP 已发送 2 次”，随后看到“已确认: STOP”。若最终显示确认超时，说明电脑已写串口，但 MCU 没有返回有效 RESPONSE，应重点检查固件版本和 `USB-TTL TX → PB4` 下行线路。

### 12.7 触觉测试

1. 先使用 0.10 A 会话限流；
2. 停机状态写入较小触觉参数；
3. 应用 Damping，START后检查阻尼方向；
4. STOP后依次测试 Spring、Detent、Limit；
5. 如果偏离中心时电机继续向外推，立即 STOP，检查 `uvw_dir` 与实际力矩方向；
6. 验证MT6826S跨0/32767时连续角和恢复力没有反向跳变；
7. 拔掉串口，确认不超过约500 ms进入停机并释放HOST。

## 13. 当前限制和后续建议

以下内容当前尚未完整实现：

1. `stop_reason` 目前固定为0；上位机能看到已经停止，但不能区分用户STOP、失联和故障停机历史。
2. fault_bits 目前只上报编码器过期和参数错误，尚无母线电压、温度、硬件过流等真实采样；MT6826S即时状态在STATUS的`encoder_status`字节中返回。
3. 母线电压使用固定15 V配置值，不能反映电源压降。
4. 更换编码器会使原电角度零偏和齿槽LUT失效；首次烧录1.4.0后必须重新辨识并重新标定齿槽表。
5. 无感观测器只做观察，不负责闭环接管。
6. 连续角是软件展开值，复位后丢失，不是绝对多圈编码器；两次有效采样间超过半圈时无法可靠判断方向。
7. 协议重复保护缓存最近一条有副作用的普通命令，不是完整32条历史窗口；HELLO、STOP和HEARTBEAT不进入缓存。
8. 固件 TX 只有一个正在发送缓冲和一个高优先级待发缓冲；高负载下遥测会主动丢弃，并通过计数上报。
9. 串口解析当前没有实现半帧100 ms清理计时，异常半帧可能保留到后续字节到来后再恢复同步。
10. 旧 JustFloat 函数仍保留，其他代码若再次调用会与v2数据混流；当前正式运行路径不要调用它。
11. 齿槽标定支持原始CSV和LUT CSV；目前仍由操作者手动控制正反转和判断稳定圈，没有自动换向或自动真机验收。

建议后续优先补充：真实 stop_reason、硬件故障位、远程辨识的安全交互、协议半帧超时、完整应答队列和真机自动化回归记录。
