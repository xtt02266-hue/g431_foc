# 逐点齿槽标定（固件1.12.3）

## 使用

1. 烧录固件1.12.3，重启上位机、重新连接、接管控制，保持STOPPED。先确认位置闭环能稳定定位；如需移动摩擦辅助，先启用并写入已有摩擦参数。
2. 展开“同步齿槽标定”，点击“逐点齿槽标定：128点 / 正反向各3次”。无需手动START或操作电位器。
3. 自动关闭运行补偿配置，沿用现有位置环和速度环增益。移动阶段单独调用采集前保存且启用的摩擦参数作为前馈；到位后关闭，再重新等待稳定，正式记录中摩擦和齿槽补偿均为零。位置环输出限速±30rpm，采集限流为原限流与0.20A的较小值。
4. 每次扫描先到方向对应的引导点，确保正式第一点从指定方向靠近。正向依次0～127，反向127～0，各重复三次。
5. 每点误差≤16count（约0.176°）、速度≤1rpm、无限幅时先退出移动辅助。关闭后重新连续稳定600ms，再采集500ms。等待期间偏离超过32count或速度超过2rpm会重新辅助靠近。采集中失稳则重等稳并重采该点；单点累计10秒超时则结束失败。六次扫描的等待和采集时间比原300/200ms增加约7.7分钟，实际总时间还包括移动和重试。
6. 结束自动停机并恢复模式、输入源、限流、位置环输出范围及原补偿配置。STOP、中止、故障、心跳超时仍有效。
7. 点击“查看逐圈质量报告 / 候选曲线”，显示逐点质量和正反向保持电流。合格时将128点周期插值为512点候选LUT，默认载入增益0.3、最大补偿0.01A。
8. 上传RAM、勾选启用并写入补偿配置，再进行现有RAM对照验证。确认实际效果后再保存Flash；候选表不会自动上传或保存。

128点间隔256count（2.8125°）。插值不增加真实空间分辨率。采样保存至 `calibration_runs`，包含带实际角度和目标角度的原始CSV、元数据、质量分析；合格时额外生成candidate_lut.csv。可导入目录重新分析。

## 1.12.2 编码器异常与中断报告

- SPI角度帧CRC错误时丢弃坏帧，不更新角度或最后有效采样时间。已有有效样本仅在原来的2ms新鲜度期限内继续可用；持续CRC错误导致超时，或DMA传输失败，仍触发保护停机。
- 逐点流程检测编码器错误计数变化后，取消当前保持采集段，重新等待稳定并采集当前点。离线分析仍排除错误计数变化的采集段。
- 传感器故障停机优先报告传感器异常，避免被后续控制状态变化覆盖为“控制状态中断”。
- 会话中断时，报告展示已经完整合格的正向和反向扫描曲线，供诊断。仍须全部三组正反向扫描及其它质量检查通过才允许生成LUT；诊断曲线不作为可上传候选表。

## 1.12.3 同步记录补传

- 能力bit15（0x8000）表示支持CAL_REPLAY命令。固件环形缓存扩至256条，已发送记录在覆盖前仍可补传；新会话开始后不再允许读取旧会话数据。
- 上位机发现序号间隙后优先请求缺失记录，每次最多3条；结束状态也会检查尾部缺失。只将固件返回的原始记录补入对应位置，不插值电流、不填补伪造采样、不忽略正常流中的重复记录。
- 补传请求失败、缓存已覆盖或记录没有全部补齐，仍由原有数据完整性检查拒绝生成LUT。元数据record_recovery记录能力和补回数量。旧会话已经缺失的原始记录无法靠升级追溯恢复。
- 修正DMA启动失败时提前清空待发送队列的行为：启动失败保留队列，由主循环重新尝试。正常ACK优先级保持不变。
- 旧上位机不发送补传命令，仍能使用原有采集。新上位机连接缺少bit15的旧固件，不发送补传命令，显示旧固件不支持补传。旧固件仍沿用原来的等待和采集时长。

## 质量与限制

- 每次、每方向、每点至少150个连续同步记录。停稳后位置误差≤16count、速度RMS≤1rpm、峰值≤1.5rpm，无限流、同步遗漏、传感器告警、编码器错误计数变化或补偿电流。
- 给定与实测平均Iq之差≤max(3mA,保持给定幅值的25%)；给定电流标准差≤同一阈值。
- 必须六次128点完整扫描。三个重复扫描曲线相关系数≥0.8，合成齿槽信号RMS≥max(0.5mA,三倍重复采集误差)。
- 正反向曲线半差RMS≤max(3mA,合成信号RMS的50%)，否则判定静摩擦或迟滞影响明显。保存方向差供检查，不以正反向平均声称完全消除静摩擦。
- 直接使用电磁方向带符号Iq；反向扫描不翻转电流符号。正反向平均后去均值、周期插值，不进行搜索相位或动态翻转。
- 这些检查只放行候选表，无法独立证明获得纯粹的齿槽转矩；负载、静摩擦、编码器角度误差和位置闭环性能仍可能影响结果。实际启用效果必须验证。

## 兼容协议

HELLO版本1.12.3，总能力0xFFFF。逐点标定能力为bit13（0x2000），位置摩擦前馈能力为bit14（0x4000），同步补传能力为bit15（0x8000）。原始framing v2、普通遥测schema7、原有命令及连续旋转采样schema1均保持不变。新上位机在缺少bit13的旧固件上禁用逐点按钮并提示升级。

CAL_REPLAY（0x38）请求体9字节：session:uint32、first_sequence:uint32、count:uint8，小端序，count为1～3。需HOST控制权；采集中允许，终态仍允许读取未覆盖的当前会话记录。错误长度返回INVALID_LENGTH，会话不符、范围非法或缓存过期返回NOT_READY。成功回复body采用现有type5记录payload布局（12字节头加1～3条记录），不是另一个type5帧。模式5返回schema2/68字节，其它模式schema1/64字节。读操作不改变采集进度、错误计数或待发送队列。最大回复含10字节命令头为226字节，仍在256字节payload上限内。

CAL_START（0x32）新增mode=5；mode0～4保持原语义。32字节CAL_STATUS布局不变：mode5中speed_index表示扫描重复编号0～2，reverse表示扫描方向，accepted表示当前扫描已完成点数0～128，target_rpm=0。这些逐点状态不能当成60/80/100rpm记录分析。

mode5的type5同步记录采用独立schema2，68字节：先保留schema1的64字节字段及原含义，末尾追加float32 position_target_counts。target_rpm仍表示位置环实际给定的机械速度，angle为ADC采集瞬间实际角度。记录flags中的speed_index表示扫描重复编号。只在逐点保持采集阶段产生记录，跨点时间间隔是正常现象，sequence仍连续；控制周期遗漏检查只在连续采集段内进行。

CAL_INFO在mode5返回schema2、record_size68，原176字节元数据后追加位置环Kp/Ki/Kd三个float，总188字节。启动前旧会话元数据可能是schema1，上位机读取启动后的实际元数据并冻结schema2及位置环增益。其它模式仍返回schema1、64字节记录和176字节元数据。

测试覆盖三次正反扫描、停稳超时、版本门控、记录布局、导出导入、数据缺失、位置误差及静摩擦迟滞。未代替实机定位和补偿效果验证。
