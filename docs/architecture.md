# 当前有感固件架构

## 应用入口

`Core/Src/main.c` 保留 CubeMX 初始化和前台任务。
`firmware/app/motor_system.c` 负责系统初始化入口、TIM2 的 1 ms 调度和状态灯。
TIM2 保持原次序：参数辨识调度 → 生命周期状态更新 → 周期策略 → 状态灯。

| 文件 | 职责 |
|---|---|
| `app/motor_system.c` | 初始化和定时调度入口 |
| `app/motor_control.c` | 运行请求、故障锁存、模式切换、统一停机、音乐入口 |
| `app/motor_host.c` | 主机控制权、心跳、命令校验、给定与配置、诊断读取 |
| `app/motor_calibration_session.c` | 标定启动校验、配置保存和停机恢复 |
| `app/motor_runtime.c` | 反馈更新、标定进度、强拖、音乐和模式执行次序 |
| `app/motor_modes.c` | 力矩、位置、速度计算和电位器滤波 |
| `app/motor_haptic.c` | 自由、阻尼、弹簧、档位、限位模型、参考点及 Iq 合成 |
| `compensation/motor_cogging.c` | 补偿表事务、CRC、插值、淡出、运行渐入和 Flash 记录 |
| `compensation/motor_friction.c` | 摩擦模型、配置校验和自由模式补偿模型 |
| `compensation/motor_friction_storage.c` | 摩擦配置 Flash 记录 |
| `communication/pc_protocol.c` | 协议解包、令牌与长度检查、调用命令接口、应答序列化 |

表中路径均相对于 `firmware/`。摩擦函数保留原 `motor_feedforward_*` 名称，头文件为
`motor_friction.h`；调用方和测试已经迁移。

## 数据和依赖边界

公开状态类型在 `app/motor_types.h`，生命周期命令在 `app/motor_control.h`，
主机命令与读取接口在 `app/motor_host.h`。`motor_system.h` 汇集这些声明，保留既有调用方的源代码兼容。
命令参数与状态返回沿用基础标量，协议表片段和诊断读取保留原缓冲区／快照边界。

应用内部的跨模块状态集中在 `app/private/motor_context.c/.h`，保留原变量类型和初始值。
仅应用文件包含该内部头；协议、控制算法和设备驱动通过公开接口访问应用。
应答缓存由主机模块独占；解回绕历史由周期模块独占；电位器滤波量由模式模块独占；
标定原配置由标定会话独占。前台读取 64 位触觉相对计数时，在短临界区内取得完整快照并恢复原中断状态。

应用拆分保留了策略之间必要的共享状态，没有新增并发任务或动态分配。
补偿模块独立维护模型和配置；模式计算负责根据运行模式、方向、限流和标定阶段决定如何叠加补偿。

## 正常运行模式的补偿

所有 8 个正常闭环模式均已接入齿槽和摩擦补偿，仍分别检查补偿配置使能。
齿槽默认启用；摩擦配置的出厂默认值仍为禁用，可由上位机配置或有效 Flash 记录启用。

| 模式 | 摩擦模型输入 | 齿槽模型输入 | 合成输出的约束 |
|---|---|---|---|
| POSITION | 位置环生成的目标机械 rpm | 当前机械角与实际机械 rpm | 原位置电流限幅，速度 PI 为两种前馈预留余量 |
| SPEED | 斜坡后的目标机械 rpm | 当前机械角与实际机械 rpm | 原主机限流、速度 PI 余量和输出斜率 |
| TORQUE | 实际机械 rpm | 当前机械角与实际机械 rpm | 电位器总限流 ±0.2 A；主机总限流及所设斜率 |
| FREE | 实际机械 rpm，保留原摩擦减小阻尼模型 | 当前机械角与实际机械 rpm | 原触觉总限流及输出斜率 |
| DAMPING | 实际机械 rpm，使用纯摩擦模型 | 当前机械角与实际机械 rpm | 原触觉总限流及 1 A/s 输出斜率 |
| SPRING、DETENT、LIMIT | 实际机械 rpm，使用纯摩擦模型 | 当前机械角与实际机械 rpm | 原触觉总限流，20 A/s 输出斜率 |

摩擦 Iq 从机械方向乘换相方向转换为电磁方向；齿槽表本身已使用电磁方向，不重复转换。
齿槽在正常闭环运行后按原 500 ms 渐入；停止或进入不适用状态时复位。
力矩命令与 `target_torque_nm` 仍表示不含补偿的基础给定，最终 Iq 另加补偿再限流。
主机力矩斜率同时约束基础给定和补偿后的总输出；补偿量不会写回基础命令历史。
因此正常运行中的零力矩给定可以有补偿电流，STOP 仍撤销全部输出。

标定会话保留原来的配置保存、禁用及恢复规则；逐点定位可临时使用保存的摩擦辅助，
正式采样不叠加齿槽或摩擦辅助，补偿验证会话仍按原配置工作。
辨识、音乐、开环强拖使用独立输出路径，停机及故障继续走统一安全停机。
控制周期、协议字段、补偿参数和 Flash 布局保持不变，位置触觉曲线的调整见下节。

## 三种位置触觉曲线

默认 Spring/Detent/Limit 基础刚度由 0.03/0.05/0.05 调为 0.12/0.40/0.80 A/rad。
基础阻尼仍为 0.002 A/(rad/s)，三种曲线另加 `K * 0.025 s` 的阻尼；DAMPING/FREE 不变。
这些是待实机调节的初始值，不是已完成硬件验收的最佳参数。

- SPRING：机械相对角扣除 0.15° 静区后得到 `e`，电流为
  `-K * e * (1 + min(abs(e) / (pi/2), 1)^2) - (B + K * 0.025) * omega`。
  `omega` 为实际机械 rad/s，使用多圈连续角形成扭簧，不在单圈边界换向。
- DETENT：档距为 `2*pi/count`，档心只在误差严格越过正负 0.55 档距时移动。
  误差使用“机械计数增量 × 每圈档数”的有界整数相位，阈值为 `floor(0.55*32768)`。
  跨多档由整数向上取整一次消去整档，不增加循环；往返约有 0.10 档距迟滞。
  消去整档后才换算 rad，避免累计角增大后的浮点分辨率下降及阈值处重复换档。
  档心静区为 `min(0.02*档距, 0.15°)`，恢复力在半档距内渐硬，附加阻尼使用本模式刚度。
- LIMIT：穿透角 `p = abs(rel) - half_range` 不大于零时虚拟墙电流为零。
  墙刚度按 `1 + min(p/(10°), 2)^2` 渐硬；只对向外运动加阻尼，阻尼在墙外 0.5° 内连续建立。
  模型墙力始终朝向范围内，向内退墙不产生向外阻力；实际合成输出仍受补偿、限流和斜率影响。

三种位置触觉模式的总电流斜率由 1 调为 20 A/s，每个 1 ms 周期最多变化 20 mA；
最大电流仍使用原主机限幅。较快斜率用于减少档位切换拖尾及补偿形状失真，不能代替实机稳定性测试。
`motor_haptic_reset()` 在初始化、控制历史复位和真正 START 时失效参考点，并清档心及斜率历史。
三个模式的首次实际控制周期按最新连续角锁定中心；模式变化、停机重启会重新建立参考点。
主机重复 START 幂等，不重新锁中心；启动初始化在短临界区内完成，避免先执行旧参考点。
连续机械位置使用 64 位编码器计数；Spring/Limit 及相对角遥测先减整数中心再换算为 float。
绝对连续角 float 仅作近似遥测，不作为三种触觉控制的位置基准。
测速滚动窗使用 uint32_t 模累加及显式短距离解码，跨 INT32/UINT32 边界不会触发有符号溢出；
原有 20/10/5 ms 窗口、切换迟滞与 EMA 参数保持不变。
档心、换档阈值和静区结构与 [SmartKnob 的公开实现](https://github.com/scottbez1/smartknob/blob/master/firmware/src/motor_task.cpp)
作过对照；本工程按上述电流单位及已有生命周期自行实现，没有引入其 C++、RTOS 或阻塞输出代码。

实际操作、参数单位与调节顺序见 [触觉模式调参与逻辑检查说明](触觉模式调参与逻辑检查说明.md)。

## 有感控制配置

本工程固定使用 MT6826S。已删除 `FOC_PROFILE_SENSORLESS`、`BOARD_SENSORED_CONTROL_ENABLE`、
`BOARD_AS5600_REFERENCE_ENABLE` 及相关条件分支，删除无感观测器和 AS5600 参考角代码。
主循环和板级初始化中原有的空参考角调用也已移除。
目录重构阶段保留了 CubeMX 外设配置、引脚、控制周期、控制公式、限幅、协议命令值和 Flash 分区。
随后授权的补偿接入和触觉曲线调整已在上文单独说明。

CMake 和 Keil 工程按新目录更新。Keil 的非活动 OLED／调试源码保留在导航中并设为不参与构建，
与当前 CMake 活动固件源集合一致；本次实际编译使用 Arm GNU Toolchain。
