# 3508 降低速度环 P 后的日志分析

数据文件：`D:/haptic_knob_log_20260920_224806.csv`。

分析日期：2026-09-20。电机为拆除减速器的 3508，无磁编码器。

用户补充：本次没有点击 STOP，只进行了降速操作，随后电机自行停止。

本文记录可复核的分析方法、证据、诊断依据及结论。源码参数只能说明当前工作树，CSV 没有固件版本和参数快照，不能单独证明实际烧录版本。

## 1. 核心结论

本日志记录到的主要问题是运行电流给定持续被限制在 0.400 A，目标提高后估算转速没有相应提高。从 21 秒到结束，CH11 速度 PI 输出和 CH8 系统 Iq 给定均固定在约 0.400000006 A，符合 0.4f 的浮点表示。当前代码每次接管或释放控制都会恢复默认 0.4 A，因而本次有效限流仍为 0.4 A 的可能性很高。

但用户报告的“降速后自行停止”没有被这份日志完整覆盖：最后一帧时间为 45.985 秒，目标仍为 4650 rpm，PLL 估算转速为 3135.08 rpm，Iq 给定仍为 0.4 A，valid=1。对全文件检查，CH10 没有任何大于 0.01 rpm 的下降步进。

因此需要把两个问题分开：

1. **文件内的加速受限**：有直接的 0.4 A 输出饱和证据。
2. **用户观察到的降速后停机**：是真实的操作反馈，但本 CSV 没有相应目标下降或控制清零过程，尚不能判断停机原因。

不能把 valid 始终为 1 解释成电机必然一直在正常旋转。当前转速来自观测器，没有独立机械测速；如果实际转子在文件结束前已经停止，则必须考虑失步或观测器错误跟踪的可能。

## 2. 数据范围与分析方法

共 9198 行，记录范围 0–45.985 秒，含时间和 28 个遥测通道。行数与首末时间符合约 200 Hz 的记录规模。

文件 SHA256：`B6D98977F683067FEE53E28F4146E5839E78F574760A8E4C6F52D46A526CE745`。

分析使用原始 CSV 数值，不使用上位机状态区平滑后的显示值。按时间段计算转速均值和范围、电流均值、跟踪误差 RMS、Id RMS，以及给定接近 0.4 A 的比例。

定义：

- Iq 跟踪误差：`CH2 − CH8`。
- Iq 跟踪误差 RMS：`sqrt(mean((CH2−CH8)^2))`。
- Id RMS：`sqrt(mean(CH3^2))`。
- 接近 0.4 A：CH8 ≥ 0.3999 A。本次后续平台精确等于浮点数 0.4f，不只是碰巧接近。

这些统计量受遥测采样、数字滤波和角度估算影响，不等于示波器测得的完整电流纹波或额定相电流 RMS。

## 5. 为什么修改上位机限流可能仍没起作用

当前固件路径中：

- 默认值为 `MOTOR_HOST_DEFAULT_IQ_LIMIT_A = 0.40f`。
- `Motor_System_ClaimHost()` 接管时恢复默认限流。
- `Motor_System_ReleaseHost()` 释放时恢复默认限流。
- STOP 命令会停止并释放控制。
- 写入限流命令成功后才更新 `g_host_iq_limit_a`。
- Speed 模式每拍用此值限制速度 PI 及最终 Iq 给定。

前面修改已经允许 Speed 运行中写限流，但需要重新编译烧录该固件，并运行修改后的上位机，点击“写入限流”。仅修改输入框、只更新上位机或者写入后又 STOP/重新接管，都可能导致仍用默认 0.4 A。

日志没有 `iq_limit`、命令回复或控制权记录，不能从中确定是哪一种原因。应以“设备生效”读数为准，并同时确认命令回复成功。设备确认值与曲线长期固定值若不一致，再排查烧录版本与其他限幅路径。

本次不应直接把 0.4 A 改成无限制。提高运行限流可能让加速继续，但不能证明高速角度和电流跟踪问题已经解决。

## 6. 降低 P 是否有效

当前工作树速度环为 P=0.0020、I=0.0010，电流环目标带宽 200 Hz，Iq 变化率限制 5 A/s。

上一份 22:03:07 日志中，Iq 给定最高 0.6405 A，速度 PI 输出最高约 1.063 A；约 3000 rpm 附近振荡扩大，4.860 秒出现控制清零。新日志在约 3100–3200 rpm 区间记录了较长的平台，没有捕获类似的退出过程。

这说明新记录中的控制信号没有出现上一份同样的持续放大后清零现象，但不能把改善全部归因于降低 P：本次长期被限在 0.4 A，电流、加速度和环路工作点都不同。

尤其当速度 PI 已饱和时，继续增加 P 不会增加输出，只会更早碰到上限。此时用较小的速度波动证明 P 已调好也不充分，因为输出已经被夹成了近似恒定电流。

全文件 CH10 下降步进数为 0。这只能说明本文件未显示执行中的降速斜坡，不能反过来否定用户进行了降速操作。

需要区分以下情况：

| 情况 | 需要的证据 |
|---|---|
| 降速和停机在导出窗口结束后发生 | 停机后继续采集、再导出，确保时间覆盖操作前后 |
| 上位机曲线暂停，导出的是暂停时的旧快照 | 确认暂停状态和 CSV 最后时间；解除暂停后重新采集 |
| 已操作降速，但命令未执行、被拒绝或未发送 | SET_SPEED 的请求值、回复结果、固件接受值及时间 |
| 软件失锁或心跳超时主动停机 | 停机原因、PWM 使能、控制状态、valid 变化 |
| 实际转子失步/停转，但 PLL 仍输出约 3100 rpm | 独立测速或同步实物观察，以及 PWM、BEMF 和相位误差数据 |

如果用户确认电机已在这 45.985 秒内停下，而软件仍报告高速，排查重点必须转向观测器可信度。增加限流前应先验证这一点。

## 8. 采样与硬件迹象

全文件 Iq 范围约 −0.925 至 1.723 A，Id 范围约 −1.153 至 1.220 A。U 通道电压约 1.185–2.065 V，W 通道约 1.175–2.176 V。

与上一份日志停机附近 U 通道约 0.027 V 不同，本文件没有接近电源轨的采样电压。但由于没有覆盖明确停机事件，不能因此认为停机瞬态异常已经消失。

这些 ADC 电压来自固件数字低通后的采样，且遥测频率约 200 Hz；约 3100 rpm、7 极对时电气频率约 362 Hz，存在混叠。因此 CSV 适合看电流统计和明显异常，不适合还原相电流波形。

此外 V 相是由 −U−W 重构，三相和接近零不能独立证明两个运放或相序正确。Iq/Id 同样依赖估算角度，不能作为转子角度正确的独立证据。

## 9. 下一次测试建议

1. 确认运行的是含“Speed 运行中可写限流”修改的固件，并确认上位机“设备生效”值。先解决实际采用值与输入框值不一致的问题。
2. 保持当前 P/I 和 200 Hz，避免一次改变多个条件。若实际电流与采样可信，再逐步调整限流，观察是否仍出现上一份的高速振荡。
3. 降速操作前确保正在采集；操作后继续记录几秒再导出。检查 CSV 是否真的出现目标下降，不要只依靠界面输入框。
4. 优先增加并锁存停止原因、角度来源、实际限流、PWM 使能和最后一份观测器状态。当前日志缺失这些字段，是定位自动停止的主要障碍。
5. 如果物理停转时 valid 仍为 1，增加独立测速对照，检查 BEMF 滤波延迟、模型电压与采样时序，不能用放宽失锁阈值处理。

## 10. 最终结论

文件内加速受限最直接的原因是：速度 PI 与 Iq 给定长期固定在 0.4 A；目标从 3700 提高到 4650 rpm 没有产生更多电流请求输出。降低 P 后的稳定性变化受到限流差异影响，尚不能作严格单变量结论。

用户确认降速后自行停机，但 CSV 没有记录目标下降或停机清零，因此本次不能确认停机由失锁、心跳超时还是实际失步引起。最后一帧 valid=1 也不能排除物理停转，只能说明软件当时仍判定观测有效。

本次只分析日志并生成文档，未改控制参数、未编译或烧录。
